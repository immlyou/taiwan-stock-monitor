# Product Roadmap

這份 Roadmap 依照目前產品方向排序，目標是把台股戰情中心從「資料查詢 + 策略工具」推進到「可解釋的智能投研平台」。

## 開發原則

- 先做可解釋、可驗證的量化功能，再做生成式摘要。
- 每個智能結論都要能回到資料來源與指標拆解。
- 每一階段都要有 API、前端頁面、測試與版本記錄。
- 避免一次做大型黑箱模型；先用規則化評分、歷史紀錄與逐步驗證建立信任。

## Phase 1: 台股量化評分卡

目標：為每檔股票建立 0-100 分與 A-F 評級，提供可掃描、可排序、可解釋的投研入口。

分析構面：

- 價值：PE、PB、殖利率、估值分位數
- 成長：營收 YoY/MoM、EPS 成長、毛利率趨勢
- 動能：3M/6M/12M 報酬、相對強弱、突破訊號
- 籌碼：外資、投信、自營商、大戶持股、融資融券
- 品質：ROE、ROA、負債比、營業利益率、現金流
- 風險：波動率、最大回撤、流動性、注意股/處置股

後端交付：

- `core/stock_score.py`
- `/stocks/{stock_id}/score`
- `/screener/scores`
- 評分權重設定與單元測試

前端交付：

- 個股頁新增「量化評分卡」
- Screener 結果新增總分、評級、六大構面分數
- 顏色與標籤統一：A/B/C/D/F、Strong/Neutral/Weak

驗收標準：

- 每個分數都有構面拆解與資料日期
- 缺資料時不崩潰，清楚標示 unavailable
- 可在 3 秒內產出常用股票評分

## Phase 2: 評分變化歷史

目標：記錄股票評分升降級，讓使用者知道「最近變好或變差的原因」。

後端交付：

- 每日保存 `score_history`
- `/stocks/{stock_id}/score/history`
- `/scores/upgrades`
- `/scores/downgrades`
- 評分變動原因生成：例如「動能 +12、籌碼 -8」

前端交付：

- 個股頁新增評分歷史線圖
- 新增「評分升級 / 降級」清單
- 評分 tooltip 顯示主要變動來源

驗收標準：

- 可追蹤每日評分與各構面分數
- 升降級清單可依產業、市值、分數區間篩選
- 版本說明與每日資料更新流程同步

## Phase 3: 智慧警報 2.0

目標：把目前警報從單一條件升級成多條件、跨資料源、可綁定清單的智能警報。

警報類型：

- 價格突破 + 成交量放大
- 投信連買 N 日 + 股價站上均線
- 評分升級 / 降級
- 新股票符合 Screener 條件
- 月營收或財報異常
- 新聞或社群熱度異常

後端交付：

- 多條件 alert rule schema
- `/alerts/rules`
- `/alerts/evaluate`
- 每日/盤中 evaluate job
- Telegram / Email 通知內容模板

前端交付：

- 警報設定頁支援條件群組
- Watchlist 一鍵套用警報
- 警報命中歷史與狀態管理

驗收標準：

- 同一規則可套用多檔股票或 watchlist
- 可設定頻率、冷卻時間與通知渠道
- 有測試覆蓋規則解析與命中判定

## Phase 4: 個股 AI 摘要

目標：在每檔股票頁提供可解釋的 AI 投研摘要，將量化分數、技術、籌碼、財報與新聞整合成固定格式。

摘要格式：

- 目前結論：偏多 / 中性 / 偏空
- 主要亮點
- 主要風險
- 最近 30 天變化
- 適合短線 / 波段 / 長期 的程度
- 接下來要觀察的觸發條件

後端交付：

- `/ai/stock-summary/{stock_id}`
- 結構化 prompt builder
- 引用資料摘要與 fallback template

前端交付：

- 個股頁新增「AI 摘要」區塊
- 顯示引用資料日期與主要指標
- 支援重新生成與複製摘要

驗收標準：

- AI 摘要不可只輸出空泛文字
- 每個結論至少引用 3 類資料：價格、基本面、籌碼/新聞
- API 額度或 AI 服務失敗時有 deterministic fallback

## Phase 5: 投資組合診斷

目標：讓使用者看懂投資組合風險、曝險與績效來源。

分析內容：

- 產業集中度
- 個股集中度
- 與加權指數相關性
- 波動率、VaR、最大回撤
- 報酬來源分解
- 拖累績效的持股
- 移除或調整某檔後的風險變化

後端交付：

- `/portfolios/{id}/diagnostics`
- `/portfolios/{id}/what-if`
- 產業/個股曝險計算
- benchmark comparison

前端交付：

- 投資組合頁新增診斷分頁
- 風險貢獻圖、產業曝險圖、what-if 模擬
- 自動列出前三個改善建議

驗收標準：

- 診斷可在沒有即時報價時用最新收盤價 fallback
- what-if 模擬不改動真實持倉
- 所有建議都顯示依據，而不是直接下買賣結論

## Phase 6: 產業輪動雷達

目標：建立台股產業強弱與資金輪動視圖，協助找出正在轉強或轉弱的族群。

分析內容：

- 產業 1D/5D/20D/60D 報酬
- 相對加權指數強弱
- 三大法人資金流
- 產業內強勢股比例
- 熱度與新聞數量

後端交付：

- `/market/industry-rotation`
- 產業分組與分數計算
- 強弱切換偵測

前端交付：

- 新增產業輪動雷達頁或整合到產業分析
- 四象限：轉強、強勢延續、轉弱、弱勢延續
- 點擊產業下鑽個股

驗收標準：

- 每個產業至少顯示動能、資金、廣度三類分數
- 可找出最近轉強產業與代表個股
- 與現有熱力圖資料共用，不重複載入大型資料

## Phase 7: 自訂 Dashboard

目標：讓使用者把 watchlist、KPI、圖表、警報、策略結果與 AI 摘要放在同一頁，形成個人投研工作台。

功能內容：

- Widget 化：Watchlist、評分升降級、警報、產業輪動、投資組合診斷、AI 晨報
- 儲存 dashboard layout
- 多 dashboard：短線、波段、長期投資、投資組合管理
- 預設模板

後端交付：

- `/dashboards`
- `/dashboards/{id}`
- layout schema 與 user settings 儲存

前端交付：

- Dashboard builder
- Widget add/remove/reorder
- 預設模板與空狀態

驗收標準：

- Dashboard 設定持久化
- 手機版仍可正常閱讀與操作
- Widget 資料載入失敗時不影響整頁

## 建議里程碑

- M1：Phase 1 完成，建立量化評分核心。
- M2：Phase 2 + Phase 3 完成，讓評分可追蹤、可觸發警報。
- M3：Phase 4 完成，AI 摘要建立明確投研輸出。
- M4：Phase 5 完成，投資組合從記帳變成診斷工具。
- M5：Phase 6 + Phase 7 完成，形成完整個人投研工作台。

## 每階段完成定義

- API endpoint 完成且有測試。
- 前端頁面可用且 mobile/desktop 不破版。
- 文件與設定頁版本記錄更新。
- `npm run lint`、`npm run build`、`pytest` 通過。
- 若影響 production，完成 Vercel 部署並確認正式網址回應 200。
